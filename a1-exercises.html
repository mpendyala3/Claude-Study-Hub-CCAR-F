CCAR-A1 Exercises · hands-on

Twenty-four exercises, graded against the exam's rules

Most are checked in your browser as you type — write the real configuration, the real schema, the real hook, and see exactly which requirements you missed. Three are terminal labs you run on your own machine, because the exit-code semantics of a hook only become permanent once you have watched one block an edit.

Two tracks on this page Exercises 1–16 are the original drills: one configuration surface, one schema, one hook at a time. Exercises 17–24 are the build track, added because the exam asks you to design whole systems rather than single objects: a PR-review multi-agent pipeline, a support orchestrator's tool distribution, the context contract between orchestrator, subagent and synthesis stage, and an orchestrator loop that cannot silently drop a session. Start with the drills if you are new to a topic; the build track is where the exam actually lives.
Work them without the reference solution open Every exercise reveals a full worked answer, but the checklist is the teaching device: it names each requirement the exam grades on. Get to a partial score first, read which checks failed, and fix them — that loop is what transfers to exam day. Your editor contents are saved locally in this browser, so you can come back to a half-finished answer.

Browser-graded

Write JSON or code into the editor and hit Check. Each check is a requirement the exam actually tests, phrased so a failure tells you what to change.

Classification drills

Fast recall for the decisions the exam repeats: which config surface, which hook event, which intervention, escalate or not.

Terminal labs

Run against a real Claude Code install. Deliberately break things — wrong exit code, wrong matcher, missing -p — and watch the failure mode.
