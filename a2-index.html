Priority 1 — the seven zeros

Every one of these is a design-judgement objective: pick the right architecture, the right isolation boundary, the right tool set, the right call order. None of them is recall. They are documented in depth on the CCAR-A2 Documentation page and drilled on CCAR-A2 Exercises.

  1. O7 — Dynamic task decomposition. Decompose complex tasks into dynamically generated subtasks that adapt as new information is discovered, rather than executing a fixed sequence regardless of intermediate findings.
  2. O8 — Review architecture selection. Select the appropriate agentic review architecture—plan mode, direct execution, or multi-phase workflow—based on task scope, risk level, and human approval requirements.
  3. O13 — Review configurations. Design Claude Code review configurations that load the correct project standards, restrict unnecessary tool access, and produce structured output suitable for automated downstream processing.
  4. O14 — context: fork. Apply the context: fork frontmatter option to Skill and slash command configurations that should execute in an isolated subagent context, preventing cross-contamination of session state.
  5. O15 — Test generation quality. Improve automated test generation quality by providing existing test files as context, defining fixture conventions, and specifying criteria that distinguish meaningful behavioral tests from trivial assertions.
  6. O33 — Tool distribution across agents. Configure tool distribution in multi-agent systems by assigning each subagent only the tools required for its designated role, reducing decision complexity and preventing out-of-role tool invocations.
  7. O37 — tool_choice and sequencing. Configure the tool_choice parameter to guarantee tool invocation when structured output is required, and sequence multi-tool workflows so prerequisite data is obtained before dependent tools are called.

Priority 2 — the partial credits

  1. O3 — Self-contained subagent prompts. Construct subagent prompts that include all findings, structured data, and source metadata required for task completion without returning to the coordinator for missing context.
  2. O11 — CLI in CI/CD. Configure Claude Code CLI invocations for automated CI/CD pipelines using non-interactive flags, permission modes, and cost and turn limits that prevent runaway executions.
  3. O20 — Context management strategies. Apply context management strategies—subagent isolation, scratchpad files, and targeted file reading—to sustain coherent codebase exploration across sessions exceeding context limits.
  4. O22 — Human review routing. Design human review routing strategies that direct extractions to reviewers based on confidence scores, document characteristics, and field-level ambiguity rather than random sampling.
  5. O26 — Extraction schema design. Design extraction schemas with optional fields, nullable values, and appropriate enum definitions that allow the model to accurately represent missing or ambiguous information without fabricating values.
  6. O29 — Extraction accuracy patterns. Apply extraction accuracy patterns—structured schemas with optional fields, format normalization instructions, and few-shot examples—to reduce hallucination and improve consistency across varied document formats.
  7. O30 — False positive reduction. Reduce automated review false positive rates by supplying project-specific conventions, accepted patterns, and exclusion criteria as persistent context applied on every review.
  8. O32 — Built-in tool selection. Select the appropriate Claude Code built-in tool—Grep, Glob, Read, or Bash—based on the nature of the search or file operation required for a given codebase task.
  9. O35 — MCP server integration. Integrate MCP servers into Claude Code and agent applications by selecting the correct server scope, configuring authentication via environment variable expansion, and verifying tool discovery.
